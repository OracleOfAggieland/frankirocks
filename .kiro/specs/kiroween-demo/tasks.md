# Implementation Plan: kiroween-demo

## Overview

This plan builds `design.md` for `requirements.md` (Brief 054, `docs/briefs/054-kiroween-demo.md`). Requirement criteria are cited as R*n.m*; "P*n*" is correctness property *n* of the design; "contract question *n*" is the design's numbering (96 to 103). Code is TypeScript (Next.js 16, Node 24, Vitest 5 with fast-check). The task order is the design's Build order: wave 0 (C0), part B beside it, part E, wave 1 (C1, C2, C4, D1), wave 2 (C3, D2), wave 3 (F).

Rules for every task:

- Work on branch `lane/kiroween-demo`. Each leaf task (1.1, 1.2, …) is exactly one atomic commit. Stage by explicit path, never `git add -A` or `git add .`. Never push or deploy.
- **Who builds, and the trailer.** The Parts table of the brief says who builds each task; the task names the builder. A commit by Kiro ends with the trailer line `Built-with: Kiro`. A commit by Claude never carries it (brief 054: "Only Kiro's commits carry the Kiro trailer"); it ends with Claude's usual co-author line.
- The shell is Windows PowerShell 5.1: run commands separately or join them with `;`, never `&&`.
- **Properties come first.** Each property is its own leaf task, one fast-check file with one property, 1,000 runs, the header the other property files use. It is committed before the code it checks. Where today's code can state it, it starts as an `it.fails` case with its seed and the fix commit removes `.fails`; where the module does not exist yet, it starts as a failing import. A committed `*.property.test.ts` file is never edited to make it pass (`scripts/property-guard.mjs`); a wrong property is a stop and a report, and a new property goes in a new file. A property's seed and shrunk case go in the task's Notes before any fix.
- "Depends on" lists tasks that must be committed first. "Witness" is the command or test whose success proves the task done. Every code task also leaves `npm test` green at its commit, except a property left red under the rule above.
- **No existing test is edited.** Interfaces that grow take optional fields or a union that accepts the old value, so the signed-in sample visit's tests pass as written (R23.3). A test that would need an edit is a stop and a question.
- No new record kind and no new closed record schema (R6.5). The only closed schemas that change are `BankStatusResponse` and `GoogleStatusResponse`. `docs/design/` is read-only. No Server Action, `use cache`, `next/og` or ISR. Before writing any route, `after()` use or other Next.js code, read the guide in `node_modules/next/dist/docs/` (`apps/web/AGENTS.md`).
- No wall-clock read in new code: the simulators use `new Date(ms)` with an argument only, and `scripts/clock-allowlist.json` does not grow (R24.8). Model IDs stay in Model_Config. Import boundaries hold: `packages/core` imports no I/O; `packages/server` imports neither `next` nor `apps/web`.
- Never open, print or commit any `.env` file. No paid OpenAI call runs in this lane.
- Checkpoint tasks make no commit unless a fix is needed; a fix is one commit.
