# Loader checks

Every way the seed build and load can fail a persona. `buildSeed` (`packages/server/src/seed/build.ts`) builds every row in memory first; a failure throws `SeedLoadError` naming the **check** and the **line ID**, never record content, and nothing is written. The reset route answers it as `CONFIG` ("seed:<check>"). The persona's own `kisses.test.ts` loads the fixture through the real loader, so you see the same failure under `npx vitest run packages/server/src/seed/kisses`.

Reading a failure: `seed load failed: <check> on <lineId>: <detail>`. Fix the named line, run the check again, and expect the next failure to be a different line: the build stops at the first.

## The eight checks

| Check | What triggers it | How to fix the line |
|---|---|---|
| `duplicateLine` | Two lines share an `id` (any kinds). | Give each line its own ID. IDs are global across turns, mail, bulk, calendar and bank. |
| `spanNotInEvidence` | A `q(quote, field, nth)` quote is not in that field of that line: wrong text, a different apostrophe or dash, an empty quote, an `nth` past the last occurrence, the wrong `field`, or a span on a calendar or bank line (they have no text). Also hits mention spans, `privateRead` support and counter spans, and every claims span. | Copy the quote straight out of the line's `text`, `subject` or `body`, character for character. For a repeated phrase set `nth`. Mail spans say `"subject"` or `"body"`; turn spans use the default `"text"`. |
| `packetInvalid` | A hand-written packet fails its closed schema: an ExtractV1 item with a value or args its predicate does not take, an unknown `act`, a `kind` that does not fit the predicate; a PrivateReadOwnV1 guess with an unknown `topic`; a ClaimsV1 field outside its closed shape or too many spans; **own mail carrying `claims` or `inbound`**; `origin` other than `"authored"`. New with the Kisses spec: a bank `amountCents` that is not an integer or is past `BANK_CENTS_MAX`; a bank `code` that is malformed or whose category (`bankCategoryOf`) is not the line's `category`; a bank `account` not in the profile; an invalid `demo` profile (no accounts, more than 32, duplicate `accountId`, an address that is not a plain address, a `fromSelf` mail whose `from.address` is not `demo.google.email`, a `displayName` that is not a short name); two calendar lines whose simulated event IDs collide, or two thread names that collide after mapping. | Read the detail after the colon: it names the schema path (`ExtractV1 $.items[0].args: …`). Compare with the matching line in the first persona (`packages/server/src/seed/persona/`) and with `EXTRACT_GUIDE` in `packages/core/src/extract.ts`. Remove claims from own mail. |
| `itemNotWritten` | An extract item does not plan to one **active, owner-authored Memory**. Detail shows `item <n>: <plan kind>`. Typical: **`hold`** for an item with `predicate: "allergy"` and `kind: "rule"` (the seed cannot write hard rules; the live route does), or for an item the planner refuses; a plan that is not a Memory; a Memory that is not active or whose class is not `U`. | Re-file the fact. For an allergy use a `fact` (`args: { topic: "food", label: "allergy" }`, `sens: "S1"`) quoting his words, and/or `preference.food` with code `avoid`. Check the item against the predicate table in `fixture-format.md`. Turn a "maybe" into a statement the owner actually made; `hypothetical`, `joke`, `venting` and `quote` acts write nothing, so do not use them. |
| `sameKey` | Two items, in one turn or across turns, would write the same Memory key: the same predicate and scope for a single-valued predicate (`identity.name`, `place.residence`, `employment.status`, a second `preference.style` with the same context and dimension), or the same claim twice. The seed never supersedes. | Keep one, or make the second a different fact: change `args.label`, `args.context`, `args.dimension` or the mention. Do not repeat a name or an address in a later turn. |
| `recordInvalid` | A built record fails its closed schema: an Evidence, a Memory, a Job, a calendar revision or a bank row. Detail names the line and the schema path (`evidence $.…`, `memory 0 …`, `revision 2 …`). Typical: a field past its schema bound (a long body, subject, title or merchant name, too many recipients), an `at` that does not resolve to an instant, a `sens` outside `S0` to `S2`. | Shorten or fix the field the path names. Mail bodies in a persona are short (a few sentences). |
| `lineage` | W-LINEAGE: a Memory's roots do not resolve through its spans to Evidence text that matches. Detail lists the failure codes. | Almost always a span that is not exact (fix as `spanNotInEvidence`), or an item whose quote is not in the line it is on. A Memory must quote the turn it came from, never another. |
| `bulkNotLogistics` | A `bulk: true` mail line carries a promise (`senderPromises`), a claim about the user (`claimsAboutUser`), a topic signal (`topicSignals`) or `directiveCount > 0`. Bulk mail is logistics-only (contracts §4). | Leave only `logistics` on bulk lines, or take the line out of bulk. A stranger's instruction is **not** bulk mail (`trust.md`). |

## Failures the load does not name

These do not throw, but a test or a review catches them:

- **The hero is not offered.** `takeoutLateMeetingV1` returns something other than `eligible` and `mostly`. Re-do the arithmetic in `skeleton.md`: six or more posted takeout orders, a majority of count **and** cents on dates with an accepted opaque meeting at or after 18:00, 14 or more dates with a bank row, no pending row inside the window.
- **The name never reaches the Head.** Jeffrey's name needs an `identity.name` (or `identity.alias`) item for `self` whose value is a short name: at most 40 characters and four words, letters, apostrophes, hyphens and initials only. Anything else is "a name the owner gave" but not safe for the instruction line.
- **A packet quotes the wrong turn.** A span that quotes a different line's text fails `spanNotInEvidence`; one that quotes words that do not say the fact passes the load and fails the review. Read each quote as if it were the only evidence.
- **A mail address is unreadable.** The mail agent compares plain addresses only (`name@host.tld`, lower case, letters, digits and `._%+'-`). An address with a space or an angle bracket in it fails the simulated read, not the load.
- **A denied word.** The persona check (`scripts/check.mjs`) and the Taste property flag any real name or brand from the Denied_List.

## The order the build runs

Evidence and its checks line by line in fixture order (a duplicate ID stops it at once), each turn's items planned in order (so a `sameKey` clash names the later line), then W-LINEAGE over every Memory against the Evidence the seed itself holds. A `lineage` failure therefore appears only after every line passed its own checks.
